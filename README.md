# Fake NTP Server

Локальний NTP-сервер, який видає **різний час різним пристроям** залежно від їхньої IP-адреси.
Призначений насамперед для старих пристроїв, які самі не вміють коректно переходити
на літній/зимній час або мають інші нюанси синхронізації.

---

## 1. Що сервіс робить і для чого

Сервіс корисний, коли:

- пристрій (камера, старий контролер, принтер, промисловий прилад) вміє NTP, але
  **не має коректної реалізації DST**;
- пристрій жорстко налаштований на `GMT+0` або інший фіксований пояс, а потрібно,
  щоб він показував час іншої країни;
- потрібно видавати різний час різним пристроям за їхньою IP-адресою;
- потрібно «заморозити» літній час, видаючи стандартний час цілий рік;
- потрібно замінити звичайний NTP-демон на реальному сервері, зберігши можливість
  індивідуальних правил для клієнтів.

Для кожного NTP-запиту сервер знаходить правило за IP-клієнта: спочатку точний IP,
потім найконкретнішу підмережу CIDR, потім правило `0.0.0.0/0`.

Підсумковий зсув:

```
зсув = додаткова корекція (год)
     + UTC-зсув обраного часового поясу
     + зсув upstream NTP (якщо увімкнено)
```

Якщо у правила увімкнено DST — береться поточний зсув поясу з літнім часом.
Якщо DST вимкнено — стандартний зсув цілий рік.

Приклади:

| Пристрій | Правило | Що побачить пристрій |
|---|---|---|
| Камера `GMT+0`, потрібен Київ | `Europe/Kyiv`, DST увімкнено, корекція `0` | `+2` взимку, `+3` влітку |
| Камера `GMT+2`, потрібен Київ | `Europe/Kyiv`, DST увімкнено, корекція `-2` | `+0` взимку, `+1` влітку |
| Постійний Нью-Йорк без DST | `America/New_York`, DST вимкнено, корекція `0` | завжди `UTC-05:00` |
| Чистий UTC | `UTC`, корекція `0` | `UTC+00:00` |

Список поясів береться з IANA-бази `zoneinfo`. Поруч із назвою одразу вказано
стандартний UTC-зсув, а якщо зараз активний літній час — і поточний, наприклад:
`Europe/Kyiv (UTC+02:00, зараз UTC+03:00)`.

Обмеження:

- це не ієрархічний NTP-сервер для синхронізації сучасних серверів;
- веб-інтерфейс працює по HTTP з Basic-авторизацією — тільки у довіреній мережі або за VPN;
- за замовчуванням системний час не змінюється; у LXC галочку зміни часу лишайте вимкненою.

## 2. Встановлення

Усі команди виконуються від `root`, префікс `sudo` не потрібен.
Потрібні Python 3.9+ і Linux/systemd. Зовнішні `pip`-залежності не потрібні.

Якщо сервіс запускається на реальному сервері, спочатку вимкніть наявний NTP-демон,
інакше він буде конфліктувати за порт 123 і за годинник:

```bash
timedatectl set-ntp false
systemctl disable --now systemd-timesyncd chrony ntp 2>/dev/null
```

Встановіть `git`, створіть каталог і клонуйте репозитарій:

```bash
apt update && apt install -y git      # Debian/Ubuntu
# або: dnf install -y git             # RHEL/Fedora

mkdir -p /opt/fake-ntp
git clone https://github.com/realwarrior3/fake-ntp.git /opt/fake-ntp

chmod 755 /opt/fake-ntp/server.py
chmod 644 /opt/fake-ntp/config.json /opt/fake-ntp/fake-ntp.service

ln -s /opt/fake-ntp/fake-ntp.service /etc/systemd/system/fake-ntp.service
systemctl daemon-reload
systemctl enable --now fake-ntp
```

У `/etc/systemd/system/` лежить **тільки лінк**, сам юніт зберігається в `/opt/fake-ntp/`.
Усі шляхи в `server.py` рахуються від каталогу скрипта.

### Перший вхід

При першому запуску створюється `ntp.db` з правилом `0.0.0.0/0`, а `credentials.json`
створюється порожнім. Відкрийте `http://<ip-сервера>/` — побачите сторінку
**«Перше налаштування»**. Введіть логін, пароль (мінімум 8 символів) і підтвердження.
Цей перший користувач стає адміністратором (`role: admin`), після чого сторінка
перезавантажиться і запитає Basic-авторизацію з щойно створеними даними.

Пароль зберігається у `/opt/fake-ntp/credentials.json` з правами `600`:

```json
{
  "users": [
    { "username": "admin", "password": "ваш-пароль", "role": "admin" }
  ]
}
```

Щоб змінити пароль або додати користувачів, відредагуйте цей файл і перезапустіть сервіс:

```bash
nano /opt/fake-ntp/credentials.json
systemctl restart fake-ntp
```

### Оновлення

```bash
cd /opt/fake-ntp
git pull
systemctl restart fake-ntp
```

## 3. Налаштування

Усі зміни робляться у веб-інтерфейсі за адресою `http://<ip-сервера>/`.

### Правила

У картці «Додати або оновити правило» вказується:

- IP-адреса або підмережа CIDR;
- назва/примітка;
- часовий пояс зі списку (з UTC-зсувом у підписі);
- окремий toggle DST для цього поясу;
- додаткова корекція у годинах, якщо пристрій уже показує інший базовий час.

У таблиці видно поточний час, який видається пристрою, його UTC-зсув, кількість
запитів і час останнього звернення. Дані оновлюються кожні 5 секунд.
Правило `0.0.0.0/0` не видаляється — воно задає час для всіх інших IP.

### Upstream NTP

У картці «Глобальні налаштування» задаються:

- пояс і DST за замовчуванням;
- адреса upstream-сервера, наприклад `pool.ntp.org`;
- період опитування (30..86400 секунд);
- галочка **«Змінювати системний час (тільки реальний сервер)»**.

**Для LXC** галочка вимкнена: сервер лише додає різницю до NTP-відповідей, не
чіпаючи годинник контейнера. Час контейнера задає хост.

**Для реального сервера** галочка увімкнена: після успішного опитування викликається
`clock_settime(CLOCK_REALTIME, ...)` і встановлюється системний час. Потрібні `root`
або `CAP_SYS_TIME` (у Docker — `--cap-add SYS_TIME`). Час оновлюється тільки якщо
відхилення більше `clock_set_threshold` (0.5 с за замовчуванням). Після успішного
встановлення внутрішній зсув обнуляється автоматично, щоб не було подвійного обліку.
Якщо встановлення не вдалося, у статусі буде показана помилка, а NTP-відповіді
й далі коригуються зсувом.

### config.json

Додаткові параметри, які не змінюються з UI (порти, таймаути, поріг), лежать у
`/opt/fake-ntp/config.json`:

```json
{
  "ntp_port": 123,
  "web_port": 80,
  "default_timezone": "UTC",
  "default_use_dst": false,
  "upstream": {
    "enabled": false,
    "server": "pool.ntp.org",
    "port": 123,
    "timeout": 2.0,
    "sync_interval": 300,
    "set_system_clock": false,
    "clock_set_threshold": 0.5
  }
}
```

Зміни `ntp_port` і `web_port` потребують перезапуску сервісу. Решта параметрів
зберігається сюди ж із веб-інтерфейсу і застосовується одразу.

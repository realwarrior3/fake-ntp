# Fake NTP Server

Локальний NTP-сервер для **старих пристроїв**, які не вміють самостійно коректно
переходити на літній/зимній час або мають інші нюанси синхронізації.

---

## 1. Для чого це призначено

Сервіс призначений для випадків, коли:

- пристрій (камера, старий контролер, принтер, промисловий прилад тощо) вміє
  працювати з NTP, але **не має коректної реалізації DST**;
- пристрій жорстко налаштований на `GMT+0` / інший фіксований пояс, а вам потрібно,
  щоб він показував локальний час іншої країни;
- потрібно видавати **різний час різним пристроям** залежно від їхньої IP-адреси;
- потрібно тимчасово «заморозити» літній час (наприклад, видавати стандартний
  час цілий рік), не змінюючи налаштування самого пристрою;
- потрібно замінити звичайний NTP-демон на реальному сервері, зберігши при цьому
  можливість видавати різний час різним клієнтам.

### Чим сервіс НЕ є

- Це **не повноцінний системний NTP-сервер** для сучасних серверів/робочих станцій:
  він не працює з хронометричними стратами, не має ієрархії пірів і не замінює
  `chronyd`/`systemd-timesyncd` на самому хості.
- **За замовчуванням** він не змінює системний час ані хоста, ані LXC-контейнера —
  лише додає обчислений зсув до NTP-пакетів, які віддає клієнтам.
- Якщо запускати сервіс на **реальному сервері**, можна увімкнути окрему галочку
  «Застосовувати час до самої системи». Тоді сервіс після успішного опитування
  upstream встановлює системний час і виступає повноцінною заміною NTP-демона.
  У LXC цю галочку слід лишати вимкненою.
- Він не призначений для відкритого доступу з Інтернету: веб-інтерфейс працює
  по звичайному HTTP з Basic-авторизацією. Використовуйте його тільки у
  довіреній мережі або за VPN/зворотним проксі з TLS.

## 2. Структура каталогу

Весь проєкт живе в одному каталозі, наприклад `/opt/fake-ntp/`:

```
/opt/fake-ntp/
├── server.py              # вся логіка: NTP + веб-UI + API
├── config.json            # загальні налаштування (порти, пояс за замовчуванням, upstream)
├── credentials.json       # логіни/паролі веб-інтерфейсу (створюється автоматично, права 600)
├── ntp.db                 # SQLite-база правил (створюється автоматично)
├── fake-ntp.service       # systemd-юніт, що зберігається разом із проєктом
└── README.md
```

У `/etc/systemd/system/` створюється **тільки символічне посилання** — скопіюйте цю команду цілком:

```bash
sudo ln -s /opt/fake-ntp/fake-ntp.service /etc/systemd/system/fake-ntp.service
```

Якщо лінк уже існує (наприклад, після перевстановлення), використайте `ln -sf`:

```bash
sudo ln -sf /opt/fake-ntp/fake-ntp.service /etc/systemd/system/fake-ntp.service
```

Усі шляхи в `server.py` обчислюються від каталогу самого скрипта, тому
переміщення проєкту не вимагає правки коду.

## 3. Встановлення

Репозитарій публічний, тому простіше клонувати його одразу в `/opt/fake-ntp`:

```bash
sudo git clone https://github.com/realwarrior3/fake-ntp.git /opt/fake-ntp
sudo chmod 755 /opt/fake-ntp/server.py
sudo chmod 644 /opt/fake-ntp/config.json /opt/fake-ntp/fake-ntp.service

sudo ln -s /opt/fake-ntp/fake-ntp.service /etc/systemd/system/fake-ntp.service
sudo systemctl daemon-reload
sudo systemctl enable --now fake-ntp
```

> Якщо `git` не встановлено: `sudo apt install git` (Debian/Ubuntu) або
> `sudo dnf install git` (RHEL/Fedora).

### Оновлення

```bash
cd /opt/fake-ntp
sudo git pull
sudo systemctl restart fake-ntp
```

При першому запуску створюється `ntp.db` з одним правилом `0.0.0.0/0`, а от
`credentials.json` створюється **порожнім** — жоден пароль не генерується.

Відкрийте у браузері `http://<ip-сервера>/`. Поки адміністратора немає, замість
звичного інтерфейсу відкриється сторінка **«Перше налаштування»**. Введіть логін
і пароль (мінімум 8 символів), підтвердьте пароль і натисніть «Створити адміністратора».
Цей перший користувач одразу отримує роль `admin`. Після збереження файл
`credentials.json` заповнюється, а сторінка перезавантажиться і попросить
Basic-авторизацію з щойно створеними даними.

Формат файлу після першого налаштування:

```json
{
  "users": [
    { "username": "admin", "password": "ваш-пароль", "role": "admin" }
  ]
}
```

Щоб змінити пароль або додати ще користувачів, відредагуйте цей файл і перезапустіть сервіс:

```bash
sudo nano /opt/fake-ntp/credentials.json
sudo systemctl restart fake-ntp
```

> Паролів немає ані в `server.py`, ані у `fake-ntp.service`. Не додавайте їх туди.
> Повторний виклик `/api/setup` після створення адміністратора повертає `403`.

### Порти

За замовчуванням використовуються `UDP/123` (NTP) і `TCP/80` (веб).
Ці порти < 1024, тому сервіс має працювати від `root` або отримати
відповідні capabilities. Для тестів можна змінити порти у `config.json`:

```json
{
  "ntp_port": 1123,
  "web_port": 8080
}
```

Для зміни портів потрібен перезапуск сервісу.

## 4. Як обчислюється час

Для кожного NTP-запиту сервер визначає правило за IP-адресою клієнта:

1. точна IP-адреса;
2. найконкретніша підмережа CIDR (наприклад, `/32` перемагає `/24`);
3. правило за замовчуванням `0.0.0.0/0`.

Підсумковий зсув:

```
зсув = додаткова корекція (год)
     + UTC-зсув обраного IANA-часового поясу
     + зсув від upstream NTP (якщо увімкнено)
```

Якщо у правила увімкнено **DST**, береться поточний зсув поясу разом із
літнім часом. Якщо DST вимкнено — береться стандартний (зимовий) зсув цього
поясу, тобто сервер віддає один і той самий час цілий рік.

### Приклади

| Пристрій | Налаштування правила | Що побачить пристрій |
|---|---|---|
| Камера з фіксованим `GMT+0`, потрібен Київ | `Europe/Kyiv`, DST увімкнено, корекція `0` | `+2` взимку, `+3` влітку |
| Камера з фіксованим `GMT+2`, потрібен Київ | `Europe/Kyiv`, DST увімкнено, корекція `-2` | `+0` взимку, `+1` влітку |
| Пристрій, якому потрібен постійний Нью-Йорк без літнього часу | `America/New_York`, DST вимкнено, корекція `0` | завжди `UTC-05:00` |
| Пристрій, якому потрібен чистий UTC | `UTC`, DST будь-який, корекція `0` | `UTC+00:00` |

Список часових поясів береться зі стандартної бази `zoneinfo` (IANA), тому
доступні пояси всіх країн.

## 5. Upstream NTP і режим «реальний сервер»

У картці **«Глобальні налаштування»** веб-інтерфейсу можна:

- увімкнути/вимкнути використання зовнішнього NTP-сервера;
- вказати адресу сервера (наприклад, `pool.ntp.org`, `time.google.com`);
- задати період опитування (30..86400 секунд);
- увімкнути/вимкнути галочку **«Застосовувати час до самої системи»**.

### Режим контейнера (галочка вимкнена — за замовчуванням)

Сервер раз на період опитує upstream, обчислює різницю між ним і локальним
годинником і додає цю різницю **тільки до NTP-відповідей клієнтам**.
Системний час хоста/контейнера не чіпається взагалі.

Це нормальний і безпечний варіант для **LXC**: контейнер не керує годинником,
його час задає батьківський хост, тому спроби змінити час призвели б до помилок.
Помилок не виникає, бо зміни часу просто немає.

### Реальний сервер (галочка увімкнена)

Якщо сервіс запущено не в контейнері, а на звичайному Linux-сервері, увімкніть
галочку. Тоді після кожного успішного опитування upstream сервіс викликає
`clock_settime(CLOCK_REALTIME, ...)` і встановлює точний системний час.
У цьому режимі сервіс дійсно є заміною звичайного NTP-демона, але водночас
продовжує видавати індивідуальний час різним клієнтам за правилами.

Важливі деталі:

- потрібні права `root` або capability `CAP_SYS_TIME`
  (у Docker: `--cap-add SYS_TIME`, у LXC галочку лишайте вимкненою);
- час встановлюється тільки якщо відхилення перевищує `clock_set_threshold`
  (за замовчуванням 0.5 с), щоб не дерти годинник через мікросекундні коливання;
- після успішного встановлення системного часу внутрішній зсув автоматично
  обнуляється — інакше вийшов би подвійний облік (`системний час вже точний` + `ще раз додати різницю`);
- якщо встановлення часу не вдалося (наприклад, немає `CAP_SYS_TIME`), у статусі
  з'явиться окрема помилка, а NTP-відповіді й далі коригуються зсувом, тобто
  сервіс не ламається;
- якщо upstream недоступний, використовується останній відомий зсув, а у
  веб-інтерфейсі відображається помилка; у статусі завжди видно час останньої
  синхронізації й останнього встановлення системного часу.

Налаштування зберігаються у `config.json` і застосовуються без перезапуску:

```json
{
  "upstream": {
    "enabled": true,
    "server": "pool.ntp.org",
    "sync_interval": 300,
    "set_system_clock": true,
    "clock_set_threshold": 0.5
  }
}
```

## 6. Веб-інтерфейс і API

Відкрийте `http://<ip-сервера>/` і введіть логін/пароль із `credentials.json`.

Можливості:

- при першому запуску — створити логін і пароль адміністратора без генерування випадкового пароля;
- додати/змінити/видалити правило для IP або CIDR;
- вибрати будь-який IANA-часовий пояс;
- увімкнути/вимкнути автоматичний DST для окремого правила;
- додати додаткову корекцію у годинах (для пристроїв із «кривим» базовим поясом);
- змінити пояс і DST за замовчуванням;
- керувати upstream NTP і вибирати режим: контейнер (без зміни часу) або
  реальний сервер (галочка застосування часу до системи);
- бачити кількість запитів і час останнього звернення для кожного правила;
- дані оновлюються автоматично кожні 5 секунд.

API (Basic-авторизація той самий):

| Метод | Шлях | Призначення |
|---|---|---|
| `GET` | `/api/rules` | правила, список поясів, статус upstream |
| `POST` | `/api/rules` | створити/онов rule за `target` |
| `DELETE` | `/api/rules?id=ID` | видалити правило (крім `0.0.0.0/0`) |
| `POST` | `/api/settings` | зберегти глобальні налаштування |

Приклад створення правила:

```bash
curl -u admin:ПАРОЛЬ -H 'Content-Type: application/json' \
  -d '{"target":"192.168.1.51","name":"Камера двір","tz_name":"Europe/Kyiv","use_dst":1,"offset_hours":0}' \
  http://127.0.0.1/api/rules
```

## 8. Вимоги

- Python 3.9+ (модуль `zoneinfo`; на деяких ОС може знадобитися пакет `tzdata`).
- Тільки стандартна бібліотека Python — жодних `pip`-залежностей.
- Linux з systemd (або будь-який інший менеджер процесів; тоді юніт не потрібен).
- Для режиму «застосовувати час до системи» — `root` або `CAP_SYS_TIME`
  (інакше цю галочку слід лишати вимкненою).

## 9. Що не потрапляє до Git

Файл `.gitignore` виключає робочі та тимчасові файли, які створюються
під час роботи сервісу й не є частиною вихідного коду:

```
ntp.db
ntp.db-journal
*.sqlite
*.sqlite-journal
credentials.json
*.tmp
*.bak
*.log
__pycache__/
*.pyc
.pytest_cache/
.venv/
venv/
.DS_Store
Thumbs.db
```

До репозиторію заливається тільки «тіло проєкту»: `server.py`, `config.json`,
`fake-ntp.service`, `README.md` і `.gitignore`.
База даних і файл паролів створюються локально на сервері й **ніколи** не
комітяться.
